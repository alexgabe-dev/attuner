# Phase 4 performance qualification

The immutable-pack prototype is isolated from the production engine. These are single paired observations on macOS arm64, Rust 1.99.1 release, with a **warm OS cache after synthetic fixture generation**. Cold CAS means a new empty object store, not an OS-cache-cold machine. No cache purge, elevated operation, hardware reset, real installation or deployment occurred.

## Local storage experiment

Each paired format uses the same deterministic generated bytes, two complete source-hash passes, original-byte verification, file flushes, no-clobber promotion, directory synchronization and SQLite FULL commits. The laboratory omits the production engine's discovery, portable namespace inventory, multi-file transaction journal and application workflow. Its numbers therefore compare **laboratory formats**; 1.59 seconds is not a shipped Attuner capture claim.

The main workload is 10,000 unique 4 KiB files plus one 128 MiB object: **10,001 files, 175,177,728 bytes**. This is close to the Phase 2/3 10,004-file fixture but intentionally reported separately. High entropy uses a deterministic PRNG, not cryptographic randomness. Results in seconds:

| Content      | Format             | First / cold CAS | Unchanged / warm CAS | One changed file | 100 changed files |
| ------------ | ------------------ | ---------------: | -------------------: | ---------------: | ----------------: |
| Compressible | Individual objects |           46.725 |                0.938 |            0.947 |             1.373 |
| Compressible | Packs              |            1.589 |                0.789 |            0.802 |             0.835 |
| High entropy | Individual objects |           50.026 |                1.185 |            0.955 |             1.509 |
| High entropy | Packs              |            1.448 |                1.056 |            0.948 |             0.992 |

The first pack captures use five compressible packs/ten durable file flushes and seven high-entropy packs/fourteen flushes, versus 10,001 individual-object flushes. Unchanged capture writes/compresses **zero objects** in both formats. One change encodes one new identity; 100 changes encode exactly 100. Existing references remain immutable and verified.

Large-only fixtures contain four unique 32 MiB files. First captures were 0.321 s individual / 0.311 s packs (compressible), and 0.422 s / 0.435 s (high entropy). High-entropy packs require four packs/eight flushes versus four individual flushes. Their warm capture was 0.281 s versus 0.215 s individual. **Packs are not universally faster.** The current single-process peak RSS across all eight workloads was 20,758,528 bytes (19.80 MiB). The large-only “one percent” bucket is rounded up to one file, i.e. 25%; do not read it as a 1% statistical workload.

Raw data, including every verification duration and object/flush count: `artifacts/phase-4/object-pack-profile-darwin.json`. The artifact records this milestone's development prototype; it is not a reproducible signed release artifact or a statistical confidence interval.

```sh
source scripts/env.sh
cargo test -p attuner-object-pack-lab --locked -- --test-threads=1
cargo run --release -p attuner-object-pack-lab --example profile --locked
```

## Shaped HTTPS and actual WAN boundary

`apps/api/src/testing/profile-shaped-transfer.ts` exercises the real HTTPS/DPoP/Fastify/SQLite/CAS protocol with 4 MiB+17-byte compressible and high-entropy synthetic objects. A userspace TCP relay preserves end-to-end TLS and applies configured one-way propagation/serialization delays without changing OS networking. Its per-direction propagation queue is bounded at 2 MiB plus one 64 KiB chunk, with readable backpressure. Every range/full original BLAKE3 is verified. It closes connections after the first durable upload receipt, resumes the remainder and proves subsequent verified reuse sends zero blob payload bytes.

The three shapes are loopback, 80 ms RTT with 5 Mbps upload/20 Mbps download, and 160 ms RTT with 2/10 Mbps. These are **emulated latency/bandwidth**, not geographic WAN qualification. No jitter, packet loss, congestion or real WAN TCP-window model is claimed. New HTTPS connections per request are intentional and included in measurement. The test harness allocates a bounded synthetic source and bounded chunk responses; it does not change the streaming Rust engine.

| Emulated shape    | Upload including durable resume | Verified download |    Warm reuse | Blob payload on reuse |
| ----------------- | ------------------------------: | ----------------: | ------------: | --------------------: |
| Loopback          |                   0.185–0.200 s |           0.105 s | 0.020–0.021 s |                   0 B |
| 80 ms, 5/20 Mbps  |                   7.951–7.961 s |     2.104–2.154 s |       0.385 s |                   0 B |
| 160 ms, 2/10 Mbps |                 19.075–19.094 s |     4.134–4.135 s | 0.715–0.724 s |                   0 B |

Ranges are the two content cases, not confidence intervals. Wire counters include TLS/protocol overhead and are separate from blob payload counters. The relay also tests orderly TCP half-close and delayed receiver backpressure, avoiding truncation of queued response bytes.

```sh
source scripts/env.sh
pnpm exec tsx apps/api/src/testing/profile-shaped-transfer.ts
```

Results are written per OS to `artifacts/phase-4/shaped-transfer-<os>.json`. The local pack is never uploaded; existing raw content protocol/version and profile authorization remain unchanged.

Actual cache-cold and geographic WAN measurements remain open. The safe procedure is a disposable, encrypted VM/volume with synthetic fixtures, recorded OS/filesystem/hardware/toolchain, and a separately approved non-production HTTPS endpoint. After a normal controlled guest shutdown/start, measure the **first** verification/capture, then repeat warm; do not purge the host's caches or power-cycle a physical PC. Record whether the hypervisor/storage cache is actually cold. For WAN, run the same enrolled synthetic clients from the target locations, record measured RTT/throughput/loss and certificate verification, retain raw timings and compare at least three observations per workload. VPS details and separate deployment authorization are required before that endpoint is created. Until then these gates stay unqualified.

The measured reduction supports pursuing packs, while production adoption remains deferred until engine migration, mixed-version restore/application rollback, retention and platform durability gates pass.
