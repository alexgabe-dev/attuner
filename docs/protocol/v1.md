# Synchronization protocol v1 — foundation

Wire schemas live in `packages/sync-protocol/src/index.ts`; Rust manifest models live in `crates/sync-core/src/protocol.rs` and are re-exported by `lib.rs`. Both consume `fixtures/protocol/manifests.json` and `hashes.json`. Unknown manifest properties are rejected. Phase 2 preserves these wire contracts and applies stricter namespace checks inside the local engine.

## Manifest

A manifest has `protocolVersion: 1`, RFC UUID `profileId`, positive 32-bit `policyVersion` and up to 100,000 file entries. Each entry has logical `root` (`account`, `character`, `addons`), portable relative `path`, lowercase BLAKE3-256 `hash`, safe integer byte `size` and consistency `group`.

Portable paths are NFC-normalized UTF-8, at most 1,024 bytes overall and 255 bytes per segment. Reject absolute/empty segments, traversal, Windows drive/stream delimiters, backslashes, reserved device names, trailing spaces/dots, controls and illegal Windows punctuation. Reject case-insensitive duplicate and file/directory ancestor collisions. Real platform adapters must additionally validate their actual filesystem behavior and handle Unicode equivalence conservatively.

Hash original bytes. Do not rewrite line endings or Lua. The manifest is logical; physical installation paths and account mappings are device-local.

## Planned prepare/commit flow

Stable complete local scan → three-way baseline/local/head comparison → explicit changes and coverage → prepare candidate → transfer missing verified blobs → compare-and-swap commit → stage and back up → guarded application → verification → device acknowledgement.

`beforeHash` and `afterHash` encode changes and deletions explicitly. Null/null and identical-hash changes are invalid. Policy changes, excluded paths and missing roots are never deletions. Stale expected head returns `HEAD_MOVED`, never a forced overwrite. A first device cannot publish an empty tree as a deletion of server history.

Blob hash identity is always raw bytes. Zstandard will initially compress local backups/cache, with wire compression reserved for future negotiated capabilities.

## Endpoint state

Implemented: GET `/api/v1/health/live`, `/health/ready`, `/capabilities`.

All other mutations return 501 `PHASE_NOT_IMPLEMENTED`; unknown read endpoints return 404. No pairing, credentials, upload, commit, restore or event stream exists yet. Errors contain `code`, `message`, `requestId`, `retryable`.

The capabilities endpoint advertises all unavailable operations as false. Readiness reflects a real SQLite connection; it does not imply synchronization readiness.

## Non-negotiable release gate

Polling alone cannot prevent an external WoW launch racing an apply operation. Verify a launch interlock per adapter/runtime before unattended application. Until then monitor and stage only. Lua is never executed. Multi-file application requires a durable journal, verified preimages and interruption recovery.
