# Phase 3 API — implemented security and transfers

All routes use `/api/v1` over certificate-verified HTTPS. Tokens and configuration contents are excluded from server logs. JSON contracts live in `packages/sync-protocol`; Rust independently validates remote input. This is a synthetic-only development service, without deployment authorization.

## Authentication

| Method | Route                            | Access and behavior                                                                                                                                                                               |
| ------ | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| POST   | `/auth/login`                    | Local account password; exact origin, rate limit, Argon2id. Secure cookie and CSRF response.                                                                                                      |
| GET    | `/auth/session`                  | Current cookie session and CSRF value.                                                                                                                                                            |
| POST   | `/auth/logout`                   | Current cookie, origin and CSRF; deletes session.                                                                                                                                                 |
| POST   | `/auth/reauthenticate`           | Current cookie, origin, CSRF and password; renews five-minute recent-auth window.                                                                                                                 |
| POST   | `/auth/enrollments`              | P-256 DPoP, S256 challenge, state and device metadata. UUID idempotency key. Ten-minute enrollment.                                                                                               |
| GET    | `/auth/enrollments/:id`          | Signed-in browser retrieves public device approval details.                                                                                                                                       |
| POST   | `/auth/enrollments/:id/decision` | Recent browser authentication; approve explicit per-profile read/write grants or deny. Matching decision retries recover the same encrypted callback delivery.                                    |
| POST   | `/auth/token`                    | DPoP-bound code/PKCE redemption or refresh rotation, UUID idempotency key. Matching retries return the same token pair for five minutes. Reuse with a new request key revokes the refresh family. |
| POST   | `/auth/device-logout`            | Active device proof; revokes device, credentials and uncommitted jobs.                                                                                                                            |
| GET    | `/profiles`                      | Device grants intersect current ownership/membership, or current browser memberships.                                                                                                             |
| POST   | `/profiles`                      | Recent browser authentication; synthetic profile only, idempotent.                                                                                                                                |
| GET    | `/devices`                       | Current browser's devices.                                                                                                                                                                        |
| POST   | `/devices/:id/revocations`       | Recent browser authentication; owner only; revokes pending operations and credentials atomically.                                                                                                 |

DPoP proofs bind method, canonical origin/path (excluding query), timestamp, random proof ID, server nonce and access-token hash. ES256/P-256 only; no remote key URLs. Nonces expire in two minutes, proofs permit sixty seconds of clock skew, replay IDs are retained through their acceptance window. Cookie authorization is never accepted as device authorization.

## Candidate sessions and content transfer

Prefix below is `/profiles/:profileId`; every route requires a currently authorized device. Writes require both a device write grant and owner/writer membership. Mutation transactions recheck credentials and membership after I/O. No global hash-presence endpoint exists.

| Method | Route                                 | Behavior                                                                                                                                                                                                             |
| ------ | ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| POST   | `/sessions`                           | Validates publication envelope, complete root coverage, namespace, policy, consistency groups, canonical BLAKE3 identity. UUID idempotency key; creates an expiring candidate. This does **not** publish a revision. |
| GET    | `/sessions/:sessionId`                | Owner-device session status and at most 200 upload summaries.                                                                                                                                                        |
| POST   | `/sessions/:sessionId/cancellations`  | Explicit cancellation; published history cannot be cancelled.                                                                                                                                                        |
| POST   | `/sessions/:sessionId/uploads`        | Hash/size must occur in candidate. Reuses only profile-verified content, after physical verification; otherwise reserves quota and returns a stable upload ID.                                                       |
| GET    | `/uploads/:uploadId`                  | Durable ordered chunk receipts for resume, at most 256 chunks.                                                                                                                                                       |
| PUT    | `/uploads/:uploadId/chunks/:position` | Octet stream; exact 4 MiB chunk or final remainder. Position retries require identical BLAKE3 and length. Receipt follows file sync, no-clobber link publication and directory sync.                                 |
| POST   | `/uploads/:uploadId/completion`       | Requires contiguous receipts; streams original content, checks total BLAKE3/size, syncs and verifies the profile object before creating verified database references.                                                |
| GET    | `/blobs/:hash?offset=N&length=N`      | Profile grant plus verified profile reference; maximum 4 MiB range, exact `If-Match` hash. Returns ETag, X-Blob-Size and X-Blob-Offset. Reads are audited before bytes are released.                                 |

A central server admits two transfer/session bodies concurrently before parsing, with bounded chunks and manifests. Metadata mutations run through the bounded database worker. Profile quotas include retained unverified reservations, including failed/expired uploads; retrying cannot reclaim credits while bytes remain. There is no automatic GC. A 16 MiB free-space reserve is checked before writes; OS ENOSPC still fails safely if free space changes concurrently.

The Rust client handles nonce challenges, cancellation at stream boundaries, durable server upload receipts, complete hash verification after resumed downloads and zero transfer of profile-verified unchanged content. The caller supplies a verified backup reader or an owned staging stream. Successful download is not an installation/apply action. Local core verification and explicit approval remain required.

## Durability and current limits

Blob storage targets a local Unix filesystem on the central server and fails closed on a Windows server. Windows clients remain supported independently. Only server-generated UUID/hash path components reach storage; manifest paths never do. Symlinks and hard-linked objects are rejected. Server configuration and its storage parent are administrator controlled.

Crashes can retain temporary/orphan files. They confer no verified access, are never automatically trusted and consume real disk space; reserve checks keep subsequent operations fail-closed. Automated orphan reconciliation, quotas across all profiles, retention/GC and volume-loss recovery remain operational work. No automatic content deletion is provided. These limits must be resolved before production deployment.

Verified upload alone does not publish a revision or apply a local file.

## Immutable publication and history

The following routes are now implemented under the same profile prefix:

| Method | Route                         | Behavior                                                                                                                                                                                                                                                                                                                                                                     |
| ------ | ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/head`                       | Current immutable identity, policy, namespace and required roots. Device grant or browser membership.                                                                                                                                                                                                                                                                        |
| GET    | `/snapshots?before=revision`  | Newest-first immutable snapshot history, at most 200 entries.                                                                                                                                                                                                                                                                                                                |
| GET    | `/snapshots/:snapshotId`      | Exact snapshot identity and complete manifest; clients must independently validate both canonical identity and namespace/policy.                                                                                                                                                                                                                                             |
| GET    | `/activity?before=eventId`    | Profile-scoped audit history, at most 200 entries.                                                                                                                                                                                                                                                                                                                           |
| POST   | `/sessions/:sessionId/commit` | Active writer device, exact `{ "approve": true }`. Verifies physical pins outside the transaction, then atomically checks authorization, policy, session, expected ID/revision/digest, verified pins; inserts/seals snapshot and changes; advances head; records original result and audit. A lost response retries the original session. A moved head returns `HEAD_MOVED`. |
| POST   | `/acknowledgements`           | Exact snapshot ID/digest after independently verified local commit. Current profile grant; rejects regressing acknowledgements. Does not trigger filesystem application.                                                                                                                                                                                                     |

Migration 0006 seals candidate/publication identity and protects committed session state and idempotency/chunk receipts. The commit uses JSON-table insertion from the already bounded candidate, avoiding a 100,000-statement request. No content hashing or filesystem I/O occurs within SQLite's IMMEDIATE publication transaction. Audit failure rolls the entire publication back. Revisions remain safe integers; exhaustion fails closed.

Local coordinator acknowledgements and live web/desktop integration remain subsequent work. A server commit is not evidence of local application.

## Verified range index

Migration 0007 stores immutable profile-scoped chunk identities after whole-object completion. Downloads hash only intersecting verified chunks, including ranges crossing a chunk boundary, and check pinned-handle metadata before/after. Legacy objects without a complete index retain full-object verification. The complete client-side original BLAKE3 check remains mandatory. This changes server read work, not wire identity or local recovery authority.

### Connected development origin

M8 uses a loopback-only HTTPS development gateway on port 4318. It serves the existing Next app and forwards only `/api/v1/` to the fixed HTTPS API on port 4317, verifying its explicitly supplied development CA. The API's configured public origin is the gateway origin, so Secure cookies, Origin checks and native DPoP proofs all identify the same external origin. This is development tooling, not a production reverse proxy or deployment. Production still requires an operator-managed TLS endpoint. Private TLS keys remain encrypted and their passphrases remain in memory; no system trust store is changed.

## M8 management and source-device reviews

All routes below are profile-authorized. Cookies require Origin/CSRF on writes; device requests require current proof-bound credentials and scope. Read pagination is bounded to 200 rows. Large manifests/proposals/previews share the two-slot admission limit.

| Method | Profile-relative route                                   | Behavior                                                                                                                                                                                                                                                                                                                            |
| ------ | -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PUT    | `/jobs/:jobId`                                           | Source device reports an optimistic generation, captured L digest, B/R identities, phase, publication/session identity and optional native-validated proposal. Full L is sent once per client cache; a missing cache returns 428. Identical generations are idempotent, conflicting/stale generations fail, identity cannot change. |
| GET    | `/jobs?before=<cursor>`                                  | Bounded source reports, real durable uploaded-byte counts, pending proposal count and revocation metadata. Does not assert continuous presence.                                                                                                                                                                                     |
| GET    | `/jobs/:jobId/conflicts?offset=<n>`                      | Deterministic B/L/R metadata comparison, generation and head proof; 200 conflicts per page. Unknown baseline requires source-device bootstrap review.                                                                                                                                                                               |
| POST   | `/jobs/:jobId/proposals`                                 | Web writer submits complete explicit choices for the exact generation/L/R. Checks current head, uniform addon choices and candidate digest. Never publishes or touches a local filesystem.                                                                                                                                          |
| GET    | `/jobs/:jobId/proposals`                                 | The single pending immutable proposal; a device can read only its own source job’s proposal.                                                                                                                                                                                                                                        |
| POST   | `/proposals/:proposalId/withdrawals`                     | Author withdraws a pending proposal. A source validation already in flight may still record its immutable past decision; publication/application remain independent explicit approvals.                                                                                                                                             |
| GET    | `/devices`                                               | Profile-scoped enrolled devices, revocation, last foreground request and durable application receipt.                                                                                                                                                                                                                               |
| GET    | `/snapshots/:snapshotId/preview?root=<root>&path=<path>` | Snapshot metadata lookup resolves a scoped content hash, never a filesystem path. Verifies stored content, audits access and returns at most 64 KiB of escaped UTF-8 text. Binary/non-UTF8 content is not coerced or executed.                                                                                                      |

Migration 0008 stores source reports and retained immutable proposal payloads, with one pending proposal per source job. Superseding, creation, validation and withdrawal are audited in the same transaction as the corresponding state mutation. Native reports are best-effort metadata: API outages cannot prevent local recovery or roll back a committed local filesystem operation. The Rust coordinator independently validates a web proposal against its pinned generation, fresh local manifest, fresh remote head, groups and canonical result digest before entering its ordinary approval state.

Manifest wire version 1 and existing fixtures are unchanged. Shared comparison fixtures include modification/deletion, addon groups and UTF-8 ordering; the same vectors run in Rust and TypeScript.
