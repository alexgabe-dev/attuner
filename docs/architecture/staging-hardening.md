# Non-production staging boundary

The prepared target is one Linux VPS with a single HTTPS origin, Fastify/SQLite/CAS and Next.js, preserving the approved architecture. No peer-to-peer path or new backend filesystem authority is introduced. **Nothing is deployed or enabled by the renderer/tests.**

The staging default uses systemd 255+ services with `LoadCredentialEncrypted`, rather than the development-only Compose file. This supplies authenticated encrypted-at-rest secrets through per-service private runtime credentials and avoids persistent plaintext `.env`/Docker secret bind files. It is an operational packaging choice, not a change to protocol or storage architecture. No existing host settings, Keychain ACLs or service permissions have been changed.

Four isolated service users separate API/data, web, HTTPS gateway and readiness monitoring. Only the gateway receives bind-to-443 capability. Code/configuration are read-only; API writes are limited to its private data volume. The dashboard and gateway cannot read database/blob/backup secrets. The manual backup service conflicts with/stops the API and receives only its dedicated backup key. Monitor timers are supplied but never enabled by these tools. There is no automatic backup, synchronization, retention or GC policy.

Browser/desktop → gateway and gateway → API use verified TLS. Next.js binds HTTP only on loopback behind the gateway; it receives no synchronization/signing secrets. API binds HTTPS on loopback. The public origin is fixed and must match CSRF/DPoP proofs; the gateway preserves Origin/authorization/cookies/proofs while overwriting forwarded client-address headers. Fastify trusts forwarded addresses only from loopback when explicitly configured; authentication never trusts a forwarded origin. Unknown upstream CA/name, missing runtime credentials, low reserve or incomplete restore fails closed.

The gateway streams request/response bodies without temporary-body caching, bounds sizes/time/connections/login rate, and logs only a generated ID, allowlisted method, broad route class, status and duration. Raw Nginx error logs are disabled because they may include request URIs; failed requests remain visible in sanitized status logs and process/service status. Fastify disables default request/error serialization and emits an allowlist of metadata, omitting headers, bodies, actual parameters, queries, errors and host names. Security audit trails remain transactional SQLite records; operational request logs are not their replacement. No telemetry is sent externally.

Storage enforces existing per-profile quota/transfer limits plus a configurable physical free-space reserve (minimum 16 MiB; staging 512 MiB). Readiness checks real database and object-store availability/reserve. A separate credential-free local HTTPS monitor returns a nonzero status on outage/low readiness; a bounded backup-receipt monitor reports stale/incomplete/corrupt latest catalog metadata without a decryption key. Receipt freshness is not proof of backup decryptability; actual encrypted restore drills remain required.

Validation uses freshly minted synthetic roots, encrypted PKCS#8 fixture keys and a private FIFO to deliver the test gateway passphrase only through kernel memory. No global trust store or persistent plaintext secret file is used. The local Mac's pre-existing Nginx and a digest-pinned official Linux Nginx image qualify actual proxy behavior independently; systemd directive validation/activation and encrypted-credential provisioning must be reported separately. An undeployed configuration is not a qualified VPS.

References: [systemd credentials](https://systemd.io/CREDENTIALS/), [systemd 255 credential loading](https://www.freedesktop.org/software/systemd/man/255/systemd.exec.html#LoadCredential=), [Nginx verified upstream TLS](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_ssl_verify), [Nginx password FIFO](https://nginx.org/en/docs/http/ngx_http_ssl_module.html#ssl_password_file). Version/security selection uses the vendor's [downloads](https://nginx.org/en/download.html) and [advisories](https://nginx.org/en/security_advisories.html): stable 1.30.6, with the official validation image pinned by OCI digest in `toolchain.json`.
