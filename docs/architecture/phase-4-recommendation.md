# Recommended Phase 4 — qualification and operational hardening

Keep real WoW access and production deployment behind separate explicit approval. Phase 3 provides the synchronization protocol; the next work should qualify its operating environment rather than add unattended behavior.

1. **Close the Windows safety gate.** Run the supplied physical Windows 11 prerequisite/desktop procedure. Implement reviewed Windows handle-relative traversal, reparse/identity checks, no-clobber mutation and durable journal/directory semantics. Qualify every apply/recovery interruption with retained-disk controlled resets, locked/read-only files, space exhaustion, antivirus interference and multiple NTFS versions. Keep apply disabled until this evidence exists. Do not power-cycle a user's physical PC as a substitute for a controlled fault environment.
2. **Establish stable desktop identity.** Signed macOS/Windows packages, explicit update trust, native secure-store reopen/rotation/revocation across upgrades, and desktop accessibility/visual qualification on both operating systems. Never broaden Keychain ACLs to work around unsigned builds.
3. **Qualify a non-production central service.** Operator-managed HTTPS/reverse proxy, service identity, persistent secret delivery/rotation, least-privilege storage, upload/request limits, disk-reserve monitoring, quota accounting and backup alerts. Exercise restart/outage/fault scenarios over realistic latency and bandwidth. No production deployment is implied.
4. **Prove disaster recovery.** Consistent SQLite+CAS backup/restore, immutable seals/audit verification, restore drills and rollback from a complete server backup. Design explicit, audited cleanup of abandoned uploads/orphans and reference-safe retention before any GC. Test audit failures and storage corruption, not only successful transfer.
5. **Improve first-capture cost safely.** Prototype the documented immutable object packs in an isolated experiment. Measure cold OS cache, warm unchanged, one-file change and WAN transfer separately; keep original-byte verification and durable recovery. Adopt only after backward-compatible corruption/crash tests beat the per-object baseline.
6. **Finish larger-workspace management.** Profile/device pagination, table virtualization, full conflict variant inspection, readable text comparison, additional local account administration and precise source-device freshness. Preserve explicit proposals/publication/application boundaries.
7. **Review real-installation prerequisites separately.** Before proposing a real adapter, define game-running/uncertain-state interlocks, version-specific discovery evidence, supported volumes, consent and recovery drills using copied synthetic layouts. Do not point the current fixture engine at a real installation or enable background sync.

Acceptance should require independent Windows and macOS artifacts, a repeatable three-client fault suite against the qualified staging service, a restored server backup verified by native clients, signed-upgrade credential tests and a security review of all new authority boundaries.
